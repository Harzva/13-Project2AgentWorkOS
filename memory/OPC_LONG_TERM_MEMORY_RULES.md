# OPC Long-Term Memory Rules

用途：把本次产品目录复盘提炼出的失败经验，压缩成以后每次项目推进都要遵守的硬规则。

## 一句话记忆收纳格

我的项目停滞通常不是因为想法少或能力弱，而是因为启动太快、版本太多、状态不落盘、发布不成闭环；未来每个想法都必须进入 Project2AgentWorkOS 的沉淀、萃取、结丹流程：先用项目卡片判断机会，再做 7 天内可交付的最小版本，最后发布、分发、复盘，并把经验炼成 Agent、Memory、Skills、MCP、Workflow、Rules 和 Hooks。

## 项目启动规则

- 任何项目如果 30 分钟内说不清用户、痛点、交付物，就先不建仓库。
- 建仓前必须确定英文仓库名、中文名、一句话定位、GitHub description。
- 已有相似项目时，默认合并，不默认新建。
- 新项目必须先写 `PROJECT_CARD.md`，再写代码。
- 每个项目必须明确类型：产品、skill、内容资产、素材库、研究资料、参考项目。
- 没有发布渠道的项目，默认还只是实验，不是公开项目。

## 项目执行规则

- 每轮任务最多 3 个验收项。
- “全面优化”必须改写成具体范围和可检查结果。
- 一次迭代只推进一个主路径，其他想法进入 `LATER.md`。
- 参考仓库必须放在 `reference/` 并写来源说明。
- 本地没有构建环境时，不强行构建生产包，改用 GitHub Actions。
- 历史对话中形成的方案，当天不落盘就视为未完成。

## 项目交付规则

- 没有 README、运行方式、截图或 Demo，不算交付。
- 公开项目必须有 License 或明确协议说明。
- 前端项目必须检查桌面、移动端、控制台错误和横向溢出。
- CLI 项目必须有安装命令、最小示例和 `--help` 截图或输出。
- App 或安装包项目必须有预览、截图、构建来源和安装风险说明。
- 项目完成时必须更新 `PROJECT_CARD.md` 的状态和下一步。

## 项目发布规则

- 只 push 不算发布，必须有 README 首屏、Pages 或 Release。
- 发布后 24 小时内必须生成一份内容分发文案。
- GitHub Pages 子路径必须显式验证。
- 每个公开项目必须有下一轮 Roadmap 或明确归档声明。
- README 首屏必须能让陌生人 30 秒内理解项目价值。
- 没有真实截图的项目，不允许包装成“生产级”。

## Agent 协作规则

- Agent 不能只给建议，必须产出文件、命令、清单或可验证结果。
- 每次项目任务必须有执行 Agent 和验收 Agent。
- 同类失败第二次出现，必须调用记忆归档 Agent。
- 新技能必须有 README、SKILL、示例、安装方式、验证方式。
- Agent 输出的方案必须转成仓库文件，否则只是对话草稿。
- 长任务结束时必须给出“下一轮只做什么”。

## 文件管理规则

- `output` 只能做暂存，7 天内必须回流、归档或删除。
- 根目录不放压缩包、安装包和临时截图。
- 每个项目只保留一个主 README，历史版本放 `docs/archive/`。
- 空目录必须删除或写明用途。
- 多版本项目必须有一个版本矩阵，说明每个版本的用途和去留。
- 参考资料和主工程必须分层，参考资料不能进入主构建路径。

## 命名规则

- 仓库名优先使用开发者能搜索到的关键词，不用内部隐喻。
- 名称必须能表达用户、对象或结果，不能只表达方法。
- 有传播潜力的项目使用短英文名，中文名作为副标题。
- 命名前先检查是否已有同类项目和是否容易拼错。
- `Compus` 这类拼写不稳定的名称必须统一改为正确或有意图的名称。

## 环境规则

- Windows PowerShell 下，Node/npm 相关 CLI 优先显式使用 `.cmd` shim，例如 `npx.cmd`、`npm.cmd`、`pnpm.cmd`。
- 不用 `Set-ExecutionPolicy` 修改用户系统策略来绕过 `.ps1` 执行限制。
- 本地缺 Flutter、Xcode、Android、Rust 或签名环境时，生产构建走 GitHub Actions。
- 本地只做预览、lint、轻量测试；跨平台产物以 CI 为准。
- 涉及账号、token、发布密钥时，不写入 README、截图或公开日志。

## OPC 闭环规则

- O 阶段必须产出项目卡片。
- P 阶段必须产出最小可交付版本。
- C 阶段必须产出发布链接、分发文案和复盘规则。
- 没有 C 阶段的项目，只能算半成品。
- 每周只允许 3 个 Active 项目，其余进入 Watch、Archive 或 Reference。

## 最硬的三条规则

1. 没有 `PROJECT_CARD.md` 的项目，不允许进入 Active。
2. 没有 README、Demo 截图、运行方式和下一步的项目，不算交付。
3. 没有发布、分发、复盘、Memory 的项目，不算闭环。
