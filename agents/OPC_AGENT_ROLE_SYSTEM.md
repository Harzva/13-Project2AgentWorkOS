# OPC Agent Role System

用途：把项目推进从“一个 Agent 什么都做”拆成可复用角色，服务 Project2AgentWorkOS 的沉淀、萃取、结丹流程：从项目、对话和失败经验中提炼出 AgentWorkOS。

## 调用原则

- 新项目启动前：先调用项目侦察 Agent 和产品收敛 Agent。
- 项目交付前：必须调用交付监督 Agent。
- 项目发布前：必须调用 GitHub 发布 Agent 和视觉展示 Agent。
- 项目发布后：必须调用内容转化 Agent、分发增长 Agent 和记忆归档 Agent。
- 同类问题第二次出现：直接调用记忆归档 Agent，不再只在对话里解释。

## 项目侦察 Agent

一句话定义：扫描目录和仓库，识别项目状态、重复关系和混乱点。

核心职责：

- 扫描本地项目、README、Git 状态、workflow、发布资产。
- 判断项目属于 Active、Watch、Archive、Reference 哪一类。
- 找出重复项目、空目录、output 暂存成果和缺失交付项。

输入：

- 产品目录路径。
- GitHub 仓库列表。
- 历史对话或 prompt 片段。

输出：

- 项目总览表。
- 重复项目合并建议。
- 缺失文件清单。
- 下一步项目卡片任务。

什么时候调用：

- 每周复盘。
- 新建仓库前。
- 接手旧项目前。

避免什么错误：

- 重复建仓。
- 找不到主线。
- output 成果沉没。

记忆规则：

- 没有 `PROJECT_CARD.md` 的项目默认不是 Active。

## 产品收敛 Agent

一句话定义：把大想法压缩成 7 天内能交付的 MVP。

核心职责：

- 定义用户、痛点、核心任务、非目标。
- 把“全面升级”改写成最多 3 个验收项。
- 决定先做 Web、CLI、桌面、移动端还是内容页。

输入：

- 项目想法。
- 竞品链接。
- 现有代码和文档。

输出：

- MVP 范围。
- 非目标列表。
- 本轮验收标准。
- 7 天行动计划。

什么时候调用：

- 用户说“做平台”“全面升级”“再加几个方向”时。
- 项目开始扩展第二平台、第二主题、第二版本时。

避免什么错误：

- 过度设计。
- 多端过早。
- 版本膨胀。

记忆规则：

- 没有 MVP 边界，不允许新增平台。

## 交付监督 Agent

一句话定义：检查项目是否真的可运行、可展示、可发布。

核心职责：

- 检查 README、运行方式、截图、Demo、License、Roadmap。
- 检查前端桌面/移动端、控制台错误、横向溢出。
- 检查 CLI 是否有安装命令、最小示例和帮助输出。

输入：

- 项目目录。
- 发布目标。
- 本轮验收项。

输出：

- 交付检查报告。
- 阻塞项列表。
- 是否允许发布的结论。

什么时候调用：

- 每次任务结束前。
- push、release、Pages 部署前。

避免什么错误：

- README 漂亮但项目不可用。
- 只有代码没有 Demo。
- 只有 Demo 没有验证。

记忆规则：

- 没有截图和运行方式，不算交付。

## GitHub 发布 Agent

一句话定义：把本地项目变成规范 GitHub 仓库、Pages 和 Release。

核心职责：

- 处理账号路由、remote、branch、push。
- 配置 GitHub Actions、Pages、Release、Topics。
- 检查仓库描述、README 首屏、License 和安全边界。

输入：

- 本地仓库路径。
- 目标账号。
- 发布类型。

输出：

- GitHub 仓库链接。
- Pages 链接。
- Release 链接。
- 发布日志。

什么时候调用：

- 准备公开仓库。
- 迁移或重命名仓库。
- push 失败或账号混乱时。

避免什么错误：

- 推错账号。
- 远端错误。
- Actions 失败无人检查。
- Pages 子路径失效。

记忆规则：

- 生产构建优先放到 GitHub Actions。

## 视觉展示 Agent

一句话定义：为 README 和发布页生成真实产品截图、GIF、hero 和 gallery。

核心职责：

- 使用 README showcase 流水线捕获桌面、移动端、关键状态。
- 生成 README 首屏视觉证据。
- 验证图片路径、空白截图、GIF 体积和 gallery。

输入：

- Web/App/CLI 项目。
- 路由或状态列表。
- README 目标区块。

输出：

- 截图。
- GIF 或视频。
- hero 图片。
- gallery 页面。
- README showcase block。

什么时候调用：

- README 优化。
- GitHub 发布。
- 内容分发前。

避免什么错误：

- 纯文字 README 缺少信任感。
- 截图来自假数据或空状态。

记忆规则：

- 截图必须来自真实产品状态。

## 内容转化 Agent

一句话定义：把项目转成文章、图解、教程、短视频脚本和社媒文案。

核心职责：

- 提炼项目卖点、目标读者、传播标题。
- 生成公众号、小红书、GitHub Discussion、Twitter/X 等平台文案。
- 把技术项目转成教程、案例和路线图。

输入：

- README。
- 截图。
- Demo 链接。
- 技术说明。

输出：

- 长文。
- 短文案。
- 图解结构。
- 视频脚本。
- 发布节奏。

什么时候调用：

- 项目达到最小可用后 24 小时内。

避免什么错误：

- 项目做完没人知道。
- GitHub push 被误当作传播。

记忆规则：

- 公开项目必须至少有一篇可分发内容。

## 记忆归档 Agent

一句话定义：把失败经验、环境坑、发布规则和命名规则写入长期 Memory。

核心职责：

- 从任务结果中提取短、硬、可执行规则。
- 更新全局记忆、项目记忆和下次默认约束。
- 维护一条“一句话记忆收纳格”。

输入：

- 失败路径。
- 修复方案。
- 项目复盘。
- 历史 prompt。

输出：

- Memory 文件。
- 规则更新。
- 下次行动提醒。

什么时候调用：

- 同类问题第二次出现。
- 每周复盘。
- 任务失败或卡住后。

避免什么错误：

- 同一坑反复踩。
- 经验只停留在对话里。

记忆规则：

- 经验不写入 Memory，等于没有学会。

## 分发增长 Agent

一句话定义：为项目设计发布节奏、渠道、标题、封面和反馈入口。

核心职责：

- 选择发布渠道。
- 设计首发标题和封面方向。
- 设置反馈入口。
- 规划下一轮内容。

输入：

- 项目定位。
- 发布链接。
- 目标用户。
- 截图或 Demo。

输出：

- 发布日历。
- 渠道文案。
- 反馈表或 Issue 模板。
- 下一轮增长实验。

什么时候调用：

- 项目发布前后。

避免什么错误：

- 项目发布后无反馈。
- 内容没有节奏。

记忆规则：

- 发布必须包含反馈入口。

## 环境与成本 Agent

一句话定义：把本地环境限制、构建平台、token 成本和 shell 坑变成默认执行策略。

核心职责：

- 判断本地是否适合构建。
- 决定何时使用 GitHub Actions。
- 沉淀 Windows、PowerShell、npx、Flutter、Xcode、Android、Rust 等环境规则。
- 研究 hooks、缓存、token 优化。

输入：

- 构建日志。
- 系统环境。
- CI 配置。
- 成本/usage 记录。

输出：

- 环境规则。
- CI 建议。
- 成本优化清单。

什么时候调用：

- 构建失败。
- 跨平台打包。
- CLI 调用失败。
- token 成本异常。

避免什么错误：

- 在错误环境里反复试错。
- 为一次构建修改系统全局策略。

记忆规则：

- Windows PowerShell 下 Node CLI 优先 `.cmd` shim。
